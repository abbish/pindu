# 宣传素材公共标准

视频和海报共同遵循的内容、品牌与素材规则。媒介细则分别归视频质量标准和海报设计标准；单次需求归该素材的剧本或设计说明。

## 受众与发布内容

- 宣传成品面向当前说明确定的目标观众；剧本、设计说明、素材清单、制作工具、版本管理与审核证据面向策划、制作和审核人员，分别保存与交付。
- 对外成品呈现观众需要的价值、功能证据和行动信息，不包含内部产品分析、制作流程、工具名称或管理资料入口。内部方案引用产品定位与事实，不能把分析和制作记录直接当成用户文案。
- 文档受众与入口边界沿用 `../sdd-work/references/user-facing-writing.md`；制作资料可引用用户说明核对事实，不反向加入用户文档导航。

## 内容依据

- 产品定位与核心价值读 `docs/product/value-proposition.md`。综合介绍优先表达自己的英语素材 → 学练资源 → 每日学习与复习；AI 作为实现手段，用户明确要求 AI 功能主题时再按该主题组织。学习效果假设不写成已验证承诺。
- 产品名、功能和使用条件读当前产品 README；有疑问定位实际实现。不要从旧宣传文案反推产品事实。
- 每项卖点有可找到的产品证据。区分 AI 生成、AI 讲解与规则自动化；不编造效果、用户量、评价、认证或收费承诺。
- 同一批视频、海报沿用同一产品名、核心主张、功能口径与行动目标。篇幅不同时可以删减信息，不能让不同媒介对同一功能作相互矛盾的承诺。
- 综合介绍与单功能宣传分别收敛重点，不要求每份素材都塞入全部功能。用户指定的卖点与禁用措辞保存在当前剧本或设计说明中。
- “仅策划 / 先看方案”交付方案；“生成 / 修改”在已有授权内制作；“只 review”交付问题；“review 并优化”可以修正范围内的问题。制作授权不包含外部发布。

## 品牌与视觉一致性

- 产品名以 `CLAUDE.md` §1 与 README 为准；拼读现有标识见 `public/logo-maskable.png`、`public/favicon.png` 与 `src/components/AppShell/AppShell.tsx` 中的简化「拼」字标。
- 色彩从当前 `src/styles/app.css` 或已采用的宣传视觉中选择。保持同一批素材的主色、字体气质、标识样式与截图容器一致；用户明确改变风格时按新需求。
- 使用已有标识或已获采用的宣传标识，不让生成模型重新解释品牌字形，不擅自设计另一套 logo。
- 用留白、信息层级和真实产品画面表达价值。装饰不能遮挡产品证据或让文字难读；设计选择服务目标观众与观看尺寸。
- 当前视频的时长、片尾停留、封面、具体链接、配乐和颜色数值属于该片设置，不成为所有海报或视频的固定参数。

## 素材与生成

- 记录源文件、用途、真实截图/录屏/示意/AI 生成的性质，以及第三方素材的作者、许可、来源和必要改动说明。
- 按当前需求授权选素材，未经授权不用测试或回归素材作产品展示。示意画面不能冒充真实操作或真实产品界面。
- 软件截图保持宽高比，不能把原有按钮、数据或状态改成不存在的产品能力。高亮按实际图像坐标映射并核对相邻按钮。
- AI 可生成气氛、插画与背景；需要证明产品行为的界面使用真实截图或明确标注的概念稿。正式产品展示默认保留原截图与标识，文案、链接、二维码等精确元素单独排版或编码。
- 使用环境可用的图像生成工具及其规则；需要 AI 位图时不能以代码占位图冒充完成。内置工具不可用时报告缺口，不擅自改用收费 API、CLI 或要求用户提供密钥。
- 生成模型不能代替核对。逐字检查中文、英文、产品名与链接；二维码由真实目标地址编码，并在最终图上实际解码或扫描验证。

## 归档与交付

- 视频沿用 `docs/videos/README.md`；海报沿用 `docs/posters/README.md`；共同入口为 `docs/promo/README.md`。
- 保留可编辑的文字与素材来源、生成提示词（实际使用时）、制作方式、版本和对应导出记录。选定的项目资产归入工作区，不能只指向本机临时生成目录。
- 检查实际导出文件。机械检查、视觉核对、音频播放与二维码验证分别据实记录，未做的项目不填写通过。
- 不覆盖已有采用版本。用户要求发布时再处理目标平台和外部动作，生成本地素材本身不授权上传。
