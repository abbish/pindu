# Promo Video Script

产品传播工作流的内容入口。把产品事实、用户决定和镜头安排收敛成一份可制作的当前剧本，保留已有授权与修改范围。

## 按需读取

- 每次策划或修订：读 `../references/promo-standard.md`，沿用跨媒介的产品事实、品牌和素材规则。
- 新建或归档剧本：读 `docs/videos/README.md`，沿用其目录、版本与字幕管理方式。
- 续改现有视频：读对应 `docs/videos/<video>/script.md`、字幕及制作配置；先恢复当前决定。
- 选择卖点或素材：读产品 README 及其截图；功能真实性有疑问时定位实际实现，不能从旧根说明直接推导宣传承诺。
- 有裁切、示意动画或第三方影像：读 `../promo-video-review/references/quality-standard.md` 中的素材与画面部分。

## 输入

产品、用途与观众、用户当前请求、现有剧本，以及可用素材。时长、比例、旁白、重点卖点等采用用户决定或现有剧本；只有影响内容方向的缺口才需要提问。

## 负责 / 不负责

- 负责叙事、镜头顺序、逐段时长、屏幕文案、字幕、素材依据与修订记录。
- 不渲染视频，不修改应用功能，不把策划授权扩大到发布或外部上传。

## 规则

- 先理解要让观众记住什么，再安排镜头；介绍软件整体时安排可辨识的全景，细节镜头承接具体卖点。
- 每个功能承诺对应文档、截图或实际实现。AI 生成、AI 讲解与普通自动化分别准确描述。
- 素材来源与真实录屏、截图、示意动画的性质写清楚；未经授权不采用测试或回归素材作产品展示。
- 时长、片尾停留、封面、链接、禁用措辞等是单片设置，写入剧本；不从旧视频继承未适用的要求。
- 修改内容先更新剧本和相关字幕；机器制作配置随后同步。现有成片记录保持对应原剧本，不能提前登记尚未生成的新成片。
- “先规划 / 先看剧本 / 调整后再生成”只交付剧本；用户已要求制作时，完成内容调整后可继续 `../promo-video-produce/SKILL.md`，不重复请求相同授权。

## 默认执行方式

1. 恢复现有决定，确认本次需要改变的内容。
2. 核对卖点和素材，写清每段的画面、动作、主文案、补充文案与起止时间。
3. 检查时间轴是否闭合、重点是否有足够展示时间、文案是否适合实际画幅。
4. 按用户请求交付讨论稿或保存当前剧本；归档时同步字幕、索引与修订记录。

## 输出形态

剧本或链接，以及本次改动、仍待确定的内容。剧本字段以 `docs/videos/README.md` 为准，不增加无人使用的独立策划档案。

## 完成条件

用户关注的卖点都有镜头依据；时间轴覆盖预定时长；素材可找到；已有决定保留；字幕与内容同步；仅规划的请求没有触发渲染。
